## Executive summary

The engineering baseline is good:

- 276 tests pass.
- Lint is clean.
- `main` is protected by three required checks: build/test, gitleaks and CodeQL.

The problems are of three kinds:

**Notes on the failures**

- **Docs typecheck.** `apps/docs/package.json` runs `tsc --noEmit` but declares no `typescript` devDependency. CI (Linux) is green on the same commit; why `tsc` resolves there is `[hypothesis → verify]`. Fix: declare the dependency.

- **Turbo build warning.** turbo reports `no output files found for task @hirelens/api#build`; the `outputs` key in `turbo.json` needs fixing.
- **Agent file.** turbo 2.11 writes an `AGENTS.md` into the repo root when it detects an automated agent environment. One appeared during this audit and was deleted, not committed. Set `"agentGuidance": false` in `turbo.json` so tool-specific files never land in a commit (rule 1.1).

### Architecture hypotheses (A1–A10)

**A1 — CONFIRMED.**

- **How a batch runs:**
  - `runBatch` is awaited inside `POST /score` (`scoring.ts:150-156`).
  - It is an in-process pool with concurrency 2 and 5 attempts (`batch.ts:81-82,198-199`).
  - The serverless function limit is `maxDuration = 120` (`apps/web/app/api/[[...route]]/route.ts:12`).
- **The arithmetic:** 200 resumes ÷ 2 workers is about 100 sequential LLM rounds. That is far beyond 120 s.
- **What happens when it fails:**
  - The run row stays `running`. Nothing sets `failed` or reaps stale runs (`batch.ts:120-130,202-205`).
  - Failures are saved only at the end of the batch, so `retry-failed` cannot recover a killed run.
  - There is no idempotency key or in-flight guard.
  - Docker `SIGTERM` force-exits after 2 s (`main.ts:25-29`).
  - The `onProgress` hook exists but nothing uses it.

**A2 — PARTIAL.**

- **Race: REFUTED.** The append runs in one transaction under `pg_advisory_xact_lock(hashtext(orgId))` (`packages/orchestrator/src/audit.ts:31-42`), with unique `(org_id, prev_hash)` and `(org_id, hash)` indexes (`0011_audit_chain_integrity.sql:5-8`). Chains are per org.
- **Tamper-evidence limit: CONFIRMED.**
  - The chain is plain SHA-256 with no key or signature, and `orgId` and `seq` are not hashed (`core/src/audit/hashChain.ts:52-66`).
  - Triggers block `UPDATE` and `DELETE` but not `TRUNCATE`.
  - The app role can `DISABLE TRIGGER` (`audit-purge.ts:18-24`).
  - Verification exists only inside the CSV export (`sharing.ts:210-232`).
  - There are no checkpoints and no anchor.

**A3 — CONFIRMED.**

- The provider is picked on every call (`llm/failover.ts:95-127`), and each repair is a separate call.
- The chain's `modelId` is the provider ids joined with "+" (`:85-86`).
- The run row stores `promptHash: "batch:<rubricId>"` and `seed: 0` (`batch.ts:125-127`).
- `modelVersion` is never written.
- The scores table has no provider, model or hash columns.

**A4 — CONFIRMED** (partly mitigated).

- **Prompt fencing:**
  - The resume is fenced in `<resume>` tags with an "UNTRUSTED DATA" instruction (`score/engine.ts:33,100`).
  - The text is not escaped, so a literal `</resume>` closes the fence.
  - The Ask prompt (`search/index.ts:108-124`) has no data-versus-instruction rule at all.
- **Evidence check:**
  - Unverifiable quotes are zeroed and flagged for adjudication (`engine.ts:137-152`).
  - Any substring of one character or more is accepted (`evidence/textSpan.ts:13-28`).
- **Extraction:** hidden, zero-width and bidi text is not stripped in the PDF, DOCX or text paths.
- **Tests:** there are no adversarial tests or eval cases.

**A5 — CONFIRMED.** See §6, S3 and S5–S6.

**A6 — CONFIRMED.**

- The Vercel entry degrades on a bad LLM config (`apps/api/src/vercel.ts:50-61`), while the Docker entry crashes (`main.ts:17`).
- LLM config is parsed in five places.
- Compose passes 4 LLM variables to the API and **none to web** (`docker-compose.yml:50-53,72-74`). So the AI routes hosted in the web app always run heuristic in Docker.
- `/demo` says "no LLM key" even when the provider merely failed.

**A7 — CONFIRMED.**

- There is no `/v1` prefix, no version header and no deprecation policy (`app.ts:220-249`).
- The OpenAPI spec and both clients are hand-written.
- `openapi.test.ts:57-76` only checks that 18 hard-coded paths exist.
- There are three error envelopes (§4).

**A8 — CONFIRMED.**

- No RLS exists anywhere.
- Child tables are scoped through `job_id` → `jobs.org_id`, via `loadOrgJob` (`routes/jobs.ts:28-40`).
- **Defects:**
  - Cross-tenant link revocation (issue #4) ‡.
  - Analytics reads **every tenant's** decisions, then filters in JS (`analytics.ts:62-69,126-135`) ‡.
- There is no dedicated cross-tenant suite, only ad-hoc checks.

**A9 — PARTIAL.**

- **What exists:**
  - Candidates and jobs are hard-deleted with cascades and audit tombstones (`scoring.ts:527-549`, `jobs.ts:114-125`).
- **What is missing:**
  - No retention setting or purge.
  - No candidate export and no deletion-request flow.

- **Deletion conflicts:**
  - **Deleting a user who has audit rows fails.** `actor_id` is `ON DELETE SET NULL`, but the append-only trigger rejects the update (`0000:203` against `0011:29-31`).
  - Org deletion is blocked; the only way out is the test-only `purgeOrg`.

## 7. Database review

**Schema.** There are 24 tables: 7 from Better Auth and 17 domain tables. pgvector uses `vector(768)` with an HNSW `vector_cosine_ops` index.

**Migrations**

- There are 13 migrations:
  - `0010` is a no-op.
  - `0011` and `0012` are hand-written and **have no drizzle snapshots**, so the next `drizzle-kit generate` will re-emit their DDL.
- There are no down migrations. All pending migrations run in one transaction.
- Migrations run on Docker boot **and** on every Vercel build, with no migration lock, so concurrent replicas can race.
- Risky statements:
  - `0004` changes a column type from jsonb to integer (a table rewrite).
  - `0011` creates a unique index on `audit_log` non-concurrently.
  - `0011` drops and re-adds a foreign key, which validates under lock.

**Indexes**

- **Global vector index.** One HNSW index serves every tenant, with default parameters, no `ef_search` setting and a per-job filter applied afterwards. A job's own matches can be crowded out by other tenants' chunks, and search then silently falls back to keyword (`search.ts:94-107`, `0000:231`).
- **Missing indexes:**
  - `evidence.document_id`, which every cascade delete hits;
  - `bias_audit_snapshots.org_id`;
  - `candidates(created_at)` and `(job_id, created_at)`;
  - a trigram index for the `ILIKE` searches;
  - all `SET NULL` user foreign keys.

**Integrity**

- **Score retries.** Score inserts are not transactional, and a retry re-runs the whole candidate. The unique index then fails the retry, which leaves partial scores and bills the LLM again (`orchestrator/src/run.ts:95-117,337-360`; `batch.ts:162-172`).
- **Rubric versions** can collide, because `(job_id, version)` is not unique.
- **Ingest** does a check-then-insert outside a transaction. A concurrent duplicate returns a 500 and can leave an orphan candidate.
- **Talent-pool shortlisting is not audited**, although its docstring says it is (`talent-pool.ts:302-339`).

**Queries**

- **N+1 patterns:**
  - per-criterion inserts in the orchestrator;
  - sequential zip ingest;
  - a per-document loop in `/index`;
  - the cron job, which runs jobs × 4 dimensions × several queries.
- **The review queue is already fixed,** using a window function.

**Pagination**

| Endpoint | Behaviour |
|---|---|
| Candidate list | Offset, at most 100 per page, plus `count(*)` |
| Talent pool | Paged in memory over a 2000-row window that includes raw resume text |
| Jobs list | Capped at 100, with no way to reach older jobs |
| `/review`, decision history, search corpus, audit export, link lists, analytics | Unbounded |

**Connections**

- The app pool has `max: 10` and no timeouts.
- Better Auth opens a second pool.
- Nothing calls `pool.end()` on shutdown.
- Using Neon's pooled URL is documented only in a comment.

## 8. LLM & evaluation review

**Providers.** There are seven: google, anthropic, groq, openrouter, mistral, cerebras and ollama (`packages/core/src/llm/config.ts:8-15`). The Ollama default is `…/v1`, but the hints and `.env.example` say `…/api`.

**Prompts.** All prompts are inline constants:

- scoring: `score/engine.ts:26-36`
- rubric derivation: `rubric/derive.ts:16`
- Ask: `search/index.ts:118-124`
- repair round and JSON-mode suffix: `llm/generate.ts`

`/api/self-check` calls `generateObject` directly, with no repair and no fallback.

**Determinism**

- Scoring uses temperature 0. The web-hosted generators use 0.3–0.5.
- Product runs **never send a seed**, and `scoring_runs.seed` is hard-coded to 0.

**Validation**

- Output is validated against a Zod schema with one repair round (`MAX_ATTEMPTS = 2`).
- When a provider rejects the schema, the provider is switched process-wide to JSON-text mode. If that happens on the first attempt, it uses up the repair round.

**Timeouts**

- Retries back off from 5 s to 20 s.
- The 120 s overall deadline only stops further sleeps.
- **No individual LLM call has a timeout.** The only `AbortSignal` in the codebase is on the webhook fetch.

**Usage and cost**

- Token usage is taken from the final attempt only.
- It is sent to Langfuse and the logs, not stored in the database.
- **No cost is computed anywhere.**
- Cost per resume, latency and tokens per resume: `[not measured]`.

**Provenance**

- The real prompt hash (SHA-256) is kept only in audit payloads and Langfuse. `scoring_runs.prompt_hash` holds a placeholder.
- The derivation hash is returned in the response but never saved.

**Per-org provider choice** is saved and audited but **never used**: every request runs on the environment model (`apps/api/src/app.ts:116`).

**Eval harness**

- It measures direction accuracy, self-consistency, position bias, name-swap bias and rank agreement.
- Defects:
  - τ is 1 by construction (C1).
  - The report is stale.
  - There are no injection, masking or protected-proxy suites.
  - It does not run in CI.
- Real-provider numbers: `[not measured]`.
